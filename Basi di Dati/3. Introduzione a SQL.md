SQL (**Structured Query Lenguage**) è il linguaggio standard per interagire con i DBMS.

Si compone di
* **Data Definition Langage DDL**
* **Data Manipulation Language DML**

SQL **implementa il modello relazionale** e l'algebra relazionale, con alcune estensioni.

Esiste uno standard ISO per regolare il linguaggio SQL.

I **vantaggi** dell'uso di SQL sono
* Semplicità di utilizzo
* Portabilità
* Interoperabilità

Gli **svantaggi** sono invece
* Non è ideale
* Non è dettagliato: distinguiamo tra **implementarion-defined** (il provider sviluppa la funzione come vuole, ma deve essere chiara l'implementazione) e **implementation-dependent** (non ci sono vincoli sulle informazioni dell'implementazione, e nemmeno che rimanga costante nel tempo).

## Definizioni

> [!info] Catalogo
> Il **catalogo** è un **insieme di schemi**. 

La creazione di un catalogo è implementation-defined.

> [!info] Schema
> Lo **schema** è una **collezione di descrittori** di diverse tipologie di oggetti (tabelle, viste, domini, ...).

La crezione di uno schema è implementation-defined.

Un **information schema** contiene informazioni su tutti gli oggetti di un catalogo.

> [!info] Tabella
> Una tabella è una collezione ordinata di zero o più colonne e zero o più righe.
> * Le righe non sono ordinate
> * Ogni riga ha un tipo, detto row type, uguale per tutte le righe della tabella.

Una **Base table** contiene dati SQL. Non può avere colonne con lo stesso nome.

> [!info] Query
> Una **query** è un'operazione che coinvolge una o più tabelle e restituisce una tabella derivata.
> * Le righe della tabella derivata possono essere ordinate
> * La tabella ordinata può avere colonne con lo stesso nome (a differenza del modello relazionale.


## SQL e modello relazionale

A differenza di una relazione nel modello relazionale, una **tabella SQL** è un **multi-set di tuple**.
Può quindi contenere **elementi duplicati**.

Esistono diversi **livelli di conformità** allo standard SQL:

L'**entry SQL** è il livello minimo. E' simile a SQL-89 e contiene le funzionalità di base del linguaggio.
L'**intermediate SQL** contiene le funzionalità più importanti. E' il livello supportato dalla maggior parte dei DBMS commerciali.
Il **full SQL** è il massimo livello di funzionalità di SQL. Contiene una serie di funzionalità avanzate che, in caso di necessità, possono esseer aggiunte ad un DBMS. Normalmente, non c'è mai la necessità di usare completamente questo livello.

## Data Definition Language (DDL)

Consideriamo la **sintassi di PostgreSQL**.

Indicheremo come **sintassi opzionale** tutto ciò che si trova tra parentesi quadre.

Ogni **statement termina con un punto e virgola**.
### Creazione di un catalogo

La **creazione di un catalogo** avviene tramite

```
CREATE DATABASE <nome database> 
	[OWNER <username>]
	[ENCODING <encoding-name>]
```

Tale operazione crea in automatico il **public schema**, che funge da schema di default.

### Cancellazione di un catalogo

L'operazione per **eliminare un catalogo** si svolge con

```
DROP DATABASE <nome database>
```

### Creazione di uno schema

L'operazione per **creare uno schema** è 

```
CREATE SCHEMA <nome schema>
	[AUTHORIZATION <username>]
```

In cui AUTHORIZATION autorizza un particolare utente ad agire sullo schema.

#### JSON
Si tratta di tipologie di dati in grado di immagazzinare dati JSON (JavaScript Object Notation), ovvero dizionari chiave/valore.

Esistono due tipi di questo dato:
* `json` memorizza una copia esatta del testo di input.
* `jsonb` decompone i file in formato binario, il che li rende lenti da aggiungere, ma molto rapidi nella processazione dei dati. Supporta l'indicizzazione.

#### Enum
Sono tipologie di dati che contengono una serie di valori ordinati statici.
Si definisce con 

```
CREATE TYPE <enum-name> AS ENUM ('<value1>', '<value2>', ...)
```

L'ordine di aggiuta dei valori nell'enum rimarrà nella struttura.

Si possono eliminare tramtie 

```
DROP TYPE <enun-name>
	[CASCADE | RESTRICT]
```

In cui RESTRICT è l'opzione di default.

### Domini definiti dall'utente
E' possibile definire alcuni domini personalizzati tramite l'operazione

```
CREATE DOMAIN <domain-name> AS <data-type>
	[DEFAULT NOT NULL | NULL]
	[CHECK (<expression>)]
```

I domini possono essere eliminati tramite 

```
DROP DOMAIN <domain-name>
	[CASCADE | RESTRICT]
```

In cui RESTRICT è l'opzione di default.
