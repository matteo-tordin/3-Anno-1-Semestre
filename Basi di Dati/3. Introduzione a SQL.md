SQL (**Structured Query Language**) è il linguaggio standard per interagire con i DBMS.

E' composto da
* **Data Definition Langage DDL**
* **Data Manipulation Language DML**

SQL **implementa il modello relazionale** e l'algebra relazionale, con alcune estensioni.

Esiste uno standard ISO per regolare il linguaggio SQL.

I **vantaggi** dell'uso di SQL sono
* Semplicità di utilizzo
* Portabilità
* Interoperabilità

Gli **svantaggi** sono invece
* Non è ideale
* Non è dettagliato: distinguiamo tra **implementarion-defined** (il provider sviluppa la funzione come vuole, ma deve essere chiara l'implementazione) e **implementation-dependent** (non ci sono vincoli sulle informazioni dell'implementazione, e nemmeno che rimanga costante nel tempo).


## Definizioni

> [!info] Catalogo
> Il **catalogo** è un **insieme di schemi**. 

La creazione di un catalogo è implementation-defined.

> [!info] Schema
> Lo **schema** è una **collezione di descrittori** di diverse tipologie di oggetti (tabelle, viste, domini, ...).

La crezione di uno schema è implementation-defined.

Un **information schema** contiene informazioni su tutti gli oggetti di un catalogo.

> [!info] Tabella
> Una **tabella** è una **collezione ordinata di zero o più colonne e zero o più righe**.
> * Le righe non sono ordinate
> * Ogni riga ha un tipo, detto **row type**, uguale per tutte le righe della tabella.

Una **Base table** contiene dati SQL. Non può avere colonne con lo stesso nome.

> [!info] Query
> Una **query** è un'operazione che coinvolge una o più tabelle e restituisce una tabella derivata.
> * Le righe della tabella derivata possono essere ordinate
> * La tabella ordinata può avere colonne con lo stesso nome (a differenza del modello relazionale).


## Caratteristiche di SQL

A differenza di una relazione nel modello relazionale, una **tabella SQL** è un **multi-set di tuple**.
Può quindi contenere **elementi duplicati**.

Esistono diversi **livelli di conformità** allo standard SQL:

![[Pasted image 20261116142114.png|295]]

L'**entry SQL** è il livello minimo. E' simile a SQL-89 e contiene le funzionalità di base del linguaggio.
L'**intermediate SQL** contiene le funzionalità più importanti. E' il livello supportato dalla maggior parte dei DBMS commerciali.
Il **full SQL** è il massimo livello di funzionalità di SQL. Contiene una serie di funzionalità avanzate che, in caso di necessità, possono esseer aggiunte ad un DBMS. Normalmente, non c'è mai la necessità di usare completamente questo livello.

L'**alfabeto** in SQL è composto da
* Maiuscole
* Minuscole
* Numeri
* Caratteri speciali.

Un **token** è l'unità lessicale del linguaggio. Si dividono in
* Identificatori (case insensitive)
* Keyword (case insensitive)
* Literal

Un **separatore** delimita diversi token. 
Si possono usare spazi e commenti come separatori.

Le **keyword** si distinguono in **riservate** e **non riservate**:
* Quelle riservate non possono essere usate come nomi di attributi o tabelle.
* Quelle non riservate possono, e sarà il DBMS a dover dedurre cosa intendere dal contesto.

Gli **identificatori** si distinguono in **regular** e **delimited**:
* I regular sono lunghi al masssimo 128 caratteri. Il primo carattere deve essere una lettera, gli altri una combinazione di lettere e "_".
* I delimited sono lunghi al massimo 128 caratteri e sono delimitati da virgolette. Sono case sensitive.


## Data Definition Language (DDL)


> [!attention] ATTENZIONE
> Consideriamo la **sintassi di PostgreSQL**.
> Indicheremo come **sintassi opzionale** tutto ciò che si trova tra parentesi quadre.

Ogni **statement termina con un punto e virgola**.

### Creazione ed eliminazione di un catalogo

La **creazione di un catalogo** si effettua tramite l'operazione

```
CREATE DATABASE <database-name> 
	[OWNER <username>]
	[ENCODING <encoding-name>]
```

Tale operazione crea in automatico il **public schema**, che funge da schema di default.

L'**eliminazione di un catalogo** si effettua tramite l'operazione

```
DROP DATABASE <nome database>
```

### Creazione ed eliminazione di uno schema

La **creazione di uno schema** si effettua tramite l'operazione

```
CREATE SCHEMA <schema-name>
	[AUTHORIZATION <username>]
```

In cui AUTHORIZATION autorizza un particolare utente ad agire sullo schema.

L'**eliminazione di uno schema** si effettua tramite l'operazione

```
DROP SCHEMA <schema-name>
	[CASCADE | RESTRICT]
```

In cui RESTRICT è l'opzione di default.
* RESTRICT cancella lo schema solamente se è vuoto.
* CASCADE cancella lo schema e tutti i suoi oggetti, se presenti.

### Tipi di dato in SQL

| Dato                                                  | Descrizione                                                       |
| ----------------------------------------------------- | ----------------------------------------------------------------- |
| `CHARACTER (n), CHAR (n)`                             | Una stringa esattamente di n caratteri                            |
| `CHARACTER VARYING (n), VARCHAR (n)`                  | Una stringa di lunghezza massima n                                |
| `BINARY (n)`                                          | Una stringa di esattamente n byte                                 |
| `BINARY VARYING (n), VARBINARY (n)`                   | Una stringa di lunghezza massima n byte                           |
| `NUMERIC(p [, s])`                                    | Un numero con una precisione di p cifre e con s cifre frazionarie |
| `SMALLSERIAL, SERIAL, BIGSERIAL [solo in PostgreSQL]` | Un intero auto-incrementante da, rispettivamente, 2, 4, 8 byte    |
| `INTEGER`                                             | Un intero con segno, usa 4 byte                                   |
| `SMALLINT`                                            | Un intero con segno, usa 2 byte                                   |
| `BIGINT`                                              | Un intero con segno, usa 8 byte                                   |
| `DOUBLE PRECISION`                                    | Floating point da 4 byte, a 6 cifre di precisione                 |
| `BOOLEAN`                                             | Un valore logico true/false                                       |
| `DATE`                                                | Data con giorno/mese/anno (senza ora)                             |
| `TIME [WITH TIME ZONE  WITHOUT TIME ZONE]`            | Tempo del giorno (senza data) con o senza timezone                |
| `TIMESTAMP [WITH TIME ZONE \| WITHOUT TIME ZONE]`     | Data e ora con o senza timezone                                   |
| `INTERVAL x [TO y]`                                   | Intervallo di tempo                                               |

#### UUID
Questo tipo di dato memorizza uno Universally Unique Identifier (UUID).
Si tratta di una quantità a 128 bit generata in modo tale da garantire (quasi certamente) che nessun altro genererà lo stesso identificatore con lo stesso algoritmo.

#### Range
Si tratta di un tipo di dato che rappresenta un range di valori di un certo tipo (detto subtype del range).

Sono particolarmente utili per esprimere il concetto di overlapping.

Esistono diversi tipi di range built-in in PostgreSQL:
* int4range per INTEGER
* int8range per BIGINT
* numrange per NUMERIC
* tsrange per TIMESTAMP WITHOUT TIME ZONE
* tstzrange per TIMESTAMP WITH TIME ZONE
* daterange per DATE

E' comunque possibile definire tipi di range personalizzati.

#### JSON
Si tratta di un tipo di dato in grado di immagazzinare dati JSON (JavaScript Object Notation), ovvero dizionari chiave-valore.

Esistono due tipi di questo dato:
* `json` memorizza una copia esatta del testo di input. Le funzioni per operare su questo dato dovranno riprocessarlo.
* `jsonb` decompone i file in formato binario, il che li rende lenti da aggiungere, ma molto rapidi nella processazione dei dati. Supporta l'indicizzazione.

### Enumerazioni

E' possibile **definire enumerazioni** di valori tramite l'operazione

```
CREATE TYPE <enum-name> AS ENUM ('<value1>', '<value2>', ...)
```

L'ordine dei valori nell'enum rimarrà quella in cui sono stati aggiunti durante la creazione.

E' possibile **eliminare un'enumerazione** tramite l'operazione 

```
DROP TYPE <enun-name>
	[CASCADE | RESTRICT]
```

In cui RESTRICT è l'opzione di default.

### Domini definiti dall'utente

E' possibile **definire domini personalizzati** tramite l'operazione

```
CREATE DOMAIN <domain-name> AS <data-type>
	[DEFAULT NOT NULL | NULL]
	[CHECK (<expression>)]
```

E' possibile **eliminare un dominio personalizzato** tramite l'operazione

```
DROP DOMAIN <domain-name>
	[CASCADE | RESTRICT]
```

In cui RESTRICT è l'opzione di default.

### Tabelle

La **creazione di una tabella** si effettua tramite l'operazione

```
CREATE TABLE <table-name> (
	<column-name-1> <column-type-1> [<default-value-1>] [<column-constraint-1>]
	<column-name-2> <column-type-2> [<default-value-2>] [<column-constraint-2>]
	...
	[<table-constraint-1>, <table-constraint-2>, ...]
)
```

Alcuni possibili **constraints** per la definizione di tabelle:
* `NOT NULL` per esprimere che una determinata colonna non accetti valori null.
* `CHECK (<expression>)` per introdurre un vincolo di dominio ad una colonna (o di tupla se riferito all'intera tabella).
* `DEFAULT <constant> | <niladic-function> | NULL`  per inserire un valore di default in una colonna. Tale valore può essere costante, null, oppure una **funzione niladica** (ad esempio CURRENT_USER, CURRENT_DATE. etc...).

Possiamo **eliminare una tabella** tramite

```
DROP TABLE <table-name>
	[CASCADE | RESRICT]
```

In cui RESTRICT è il valore di default.
